# 현재 구조와 장기 확장 설계

## 구현된 범위

현재는 정적 호스팅으로 배포 가능한 단일 플레이어 게임입니다. 외부 npm 의존성이 없고, 게임 콘텐츠·규칙·아트·화면을 분리했습니다. 브라우저에서만 유지되는 게임 상태를 서버 계정 데이터처럼 표현하지 않습니다.

```text
data.js ──┐
          ├─ game.js (순수 게임 규칙, 검증, 직렬화) ── tests/game.test.js
          │                                      └─ tests/balance.mjs
art.js ───┼─ app.js (입력, 타이머, 화면, 저장) ─────── tests/browser.mjs
          └─ style.css
                        ↓
                  scripts/build.mjs
                        ↓
                  dist/ 정적 사이트
```

`game.js`의 액션은 입력 상태를 복제한 뒤 변경합니다. 입력 상태에 대한 부작용이 없으므로 회귀 검사와 시뮬레이션에 같은 로직을 씁니다. 랜덤 생성기를 주입할 수 있어 확률·보정 로직을 결정론적으로 재현합니다.

## 상태와 저장

저장 스키마 버전은 1이며 모든 금액·레벨·목록과 유물 ID를 검증합니다. 세이브 파일은 250KB 이하만 받습니다. 알려지지 않은 필드는 제거하고, 모든 사용자 이름은 DOM 삽입 전에 이스케이프합니다.

유물 상태는 `owned[id] = { level, copies, resonance }`로 보관합니다. 장착 목록은 고유 ID 최대 3개, 연구는 분야별 정수 단계, 지역별 방문 수·신규 발견 보정은 고정 길이 배열입니다.

자동 저장은 액션 후, 활성 화면의 주기적 체크포인트, 탭 숨김과 페이지 종료에 수행합니다. 다른 탭에서 정상 저장을 갱신하면 진행 중 탐사를 중단하고 새 상태를 반영합니다. 손상 데이터를 읽으면 원본을 별도 키에 보관하고 사용자가 현재 진행으로 대체하기 전 자동 덮어쓰기를 중단합니다.

localStorage는 트랜잭션 데이터베이스가 아닙니다. 아주 짧은 순간의 동시 쓰기를 완전히 직렬화하지 않으며, 여러 기기 간 동기화도 하지 않습니다. 운영 서버를 붙이기 전에는 경쟁·결제·실시간 거래 기능을 추가하지 않습니다.

## 콘텐츠 확장 절차

현재 저장 형식은 6개 지역, 30개 유물 기준입니다. 기존 ID는 바꾸지 않습니다. 새 지역을 출시할 때는 단순히 배열만 늘리지 않고 다음을 함께 수행합니다.

1. 신규 콘텐츠 데이터와 독자적인 아트·이야기 추가
2. 저장 버전 증가 및 순차 마이그레이션 함수 추가
3. 방문·보정 카운터를 ID 기반 맵으로 전환하거나 신규 배열 길이 마이그레이션
4. 이전 버전 세이브 fixture로 업그레이드·롤백 보관 검사
5. 기존 유물의 최대 레벨과 효용을 유지한 전체 경제 시뮬레이션
6. 오프라인 캐시 버전 변경, 실제 모바일과 저장 호환성 검사

부가 목표는 한 화면에 모두 노출하지 않고 현재 시스템을 충분히 경험한 시점에 해금합니다. 향후 후보는 지역 완성 후 서고 전시, 유물 간 짧은 에피소드, 기록가 방 꾸미기입니다. 이 후보들은 현재 기능으로 표시하지 않습니다.

## 계정·서버 운영으로 확대할 경우

현재 순수 도메인 액션을 서버의 권위 있는 명령 처리기로 이동합니다. 브라우저는 결과를 요청하고 보여 주되 잉크·보상·난수를 결정하지 않습니다.

- 계정과 세이브: `players`, `player_state`, `state_revisions`
- 원장: `commands(idempotency_key, player_id, type, payload, applied_revision)`
- 지급 내역: `resource_ledger`, `relic_grants`
- 콘텐츠 버전: `content_releases`, `balance_versions`
- 운영 지표: 탐사 실패·저장 실패·성장 구간·경제 수지. 텍스트 세이브나 개인정보를 그대로 로그에 남기지 않음

액션마다 트랜잭션, 멱등 키, revision 비교를 사용하고 서버 시각으로 휴식 보상과 탐사 시간을 계산합니다. 클라이언트 저장 가져오기는 서버 경쟁 경제에 임의 반영하지 않습니다. 출시 전에 인증, 복구, 백업 복원, 부하·장애 시험을 별도 수행해야 합니다.

## 배포와 품질 기준

빌드는 `dist/`에 필요한 파일만 복사합니다. Git 메타데이터·테스트·문서·로컬 세이브를 배포하지 않습니다. 정적 사이트이므로 서버 비밀 값이 없습니다. GitHub Pages 워크플로는 테스트·시뮬레이션 후 배포합니다.

실제 Chromium 브라우저에서 탐사, 복원, 보상, 검색, 연구, 이야기, 다시 불러오기, 5회 자동 탐사, 세이브 가져오기, 이름 이스케이프, 모바일 화면, 손상 데이터 복구, 오프라인 동작을 검증합니다. 새 기능은 도메인 규칙과 사용자 경로 둘 다 검증합니다.

미술 자산은 직접 작성한 SVG이며, 외부 게임의 캐릭터·로고·원화·음악을 포함하지 않습니다. 언어는 현재 한국어입니다. 라이브 운영·사용자 데이터 동기화·다국어 지원은 향후 독립된 개발 범위입니다.
